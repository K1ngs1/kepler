### IMPORTANT BACKGROUND
- The database already has all the tables you need: `profiles`, `catalog_cards`, `user_cards`, `trade_offers`, `trade_items`, and `trade_messages`.
- All trade state changes must go through the PostgreSQL functions defined in `supabase/migrations/002_trade_functions.sql`. These are the ONLY way to create, accept, counter, cancel, or complete a trade:
  - `propose_trade(p_recipient_id uuid, p_offered_card_ids uuid[], p_requested_card_ids uuid[])` → returns the new trade ID
  - `accept_trade(p_trade_id uuid)` → recipient accepts, atomically locks all involved cards
  - `counter_offer(p_trade_id uuid, p_offered_card_ids uuid[], p_requested_card_ids uuid[])` → replaces trade items on either side
  - `cancel_trade(p_trade_id uuid)` → either party can cancel a proposed/countered trade
  - `complete_trade(p_trade_id uuid)` → each party confirms receipt; when both confirm, trade becomes `completed`
- The Supabase client and credentials are already set up in `lib/supabase/`.
