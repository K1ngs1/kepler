### 1. Additional Database Tables & Functions
Create a new migration file `supabase/migrations/002_trade_functions.sql` with:

**a) `trade_messages` table**
- Columns: `id uuid primary key default uuid_generate_v4()`, `trade_id uuid references trade_offers(id) on delete cascade`, `sender_id uuid references profiles(id) on delete cascade`, `content text not null`, `sent_at timestamptz default now()`.
- Add RLS: users can only see messages for trades where they are initiator or recipient; sender can only insert their own messages.
- Enable it in the realtime publication.

**b) Trade logic functions (all `SECURITY DEFINER`)**

1. `propose_trade(p_recipient_id uuid, p_offered_card_ids uuid[], p_requested_card_ids uuid[])`
   - Verify each offered card is owned by the caller and has `for_trade = true`.
   - Verify each requested card is owned by the recipient and has `for_trade = true`.
   - Insert a row into `trade_offers` with `status = 'proposed'`, initiator_id = auth.uid(), recipient_id = p_recipient_id.
   - Insert into `trade_items` for each offered card with direction = 'offer', and each requested card with direction = 'request'.
   - Return the new trade id.

2. `accept_trade(p_trade_id uuid)`
   - Check caller is the recipient and trade status is 'proposed'.
   - Atomically (in a transaction block) do:
     - Update ALL `user_cards` involved in this trade (both sides) to `for_trade = false`.
     - Set trade status to 'accepted'.
   - Raise exception if any card is no longer for_trade.

3. `counter_offer(p_trade_id uuid, p_offered_card_ids uuid[], p_requested_card_ids uuid[])`
   - Caller must be a participant, status must be 'proposed' or 'countered'.
   - Delete existing `trade_items` for this trade.
   - Insert new ones as in propose_trade.
   - Reset status to 'proposed' (and update `updated_at`).

4. `cancel_trade(p_trade_id uuid)`
   - Either participant can cancel if status is 'proposed' or 'countered'. Set status to 'cancelled'.

5. `complete_trade(p_trade_id uuid)`
   - Add two boolean columns to `trade_offers` if they don’t already exist: `initiator_confirmed boolean default false` and `recipient_confirmed boolean default false`.
   - When a participant calls this function, set their confirmation flag to true.
   - When both flags are true, set status to 'completed'.

**c) Realtime publication**
Add `trade_messages` to the existing publication:
`alter publication supabase_realtime add table trade_messages;`
