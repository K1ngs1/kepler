You are continuing work on the Kepler Pokémon card trading app (https://github.com/K1ngs1/kepler). 
The project currently uses Next.js 14 + Supabase, with a polished dark-themed UI 
mirroring the original Kepler mockup.

### OBJECTIVE
Implement a fully functional, free card catalog using the TCGdex API. Every card 
must come from the live API, be stored in Supabase, and be displayed in the 
frontend catalog page – all while keeping the exact Kepler look and feel.

### WHY TCGDEX
- Completely free, no API key or rate limits.
- Provides card data (name, set, number, rarity, attacks, etc.) and high‑quality images.
- Images are served via jsDelivr CDN at:
  https://cdn.jsdelivr.net/gh/PokemonTCG/pokemon-tcg-data@latest/images/en/{set}/{number}.png
  (Example: `base1/4.png` for Base Set Charizard.)
- API docs: https://tcgdex.dev

### STEP‑BY‑STEP REQUIREMENTS

#### 1. Database Schema (if not already present)
Ensure the `cards_catalog` table exists in the Supabase migration file with EXACTLY 
these columns (add to existing migration file or create a new one in 
`supabase/migrations/`):

- `id` bigint PRIMARY KEY GENERATED ALWAYS AS IDENTITY
- `tcgdex_id` text UNIQUE (the full TCGdex item id, e.g. `"base1-4"`)
- `name` text NOT NULL
- `set_name` text NOT NULL
- `set_code` text NOT NULL (e.g. `"base1"`)
- `number` text NOT NULL (e.g. `"4"`)
- `rarity` text
- `image_url` text (the jsDelivr CDN URL)
- `created_at` timestamptz DEFAULT now()

Add an index on `(name, set_code)` for faster searches.

#### 2. Seed Script (`scripts/seed-catalog.mjs`)
Create a Node.js script that populates the `cards_catalog` table with **at least 300 
real cards** from the TCGdex API. Focus on classic English sets, e.g.:

- base1, base2, base3, jungle, fossil, basep, gym1, gym2, neo1, neo2, etc.
(Use the API to fetch all cards from these sets, or fetch the full list and filter.)

**Script behavior:**
- Read Supabase URL and anon key from environment variables.
- Fetch the card list from `https://api.tcgdex.net/v2/en/cards` (or iterate 
  over sets via `https://api.tcgdex.net/v2/en/sets`).
- For each card, extract `id` (tcgdex_id), `name`, `set` (set name), 
  `setCode`, `number` (localNumber), `rarity`.
- Construct the image URL: 
  `https://cdn.jsdelivr.net/gh/PokemonTCG/pokemon-tcg-data@latest/images/en/${setCode}/${number}.png`
- Insert the card into `cards_catalog` using the Supabase client, skipping 
  duplicates (by `tcgdex_id`).
- Implement a small delay between requests to be polite to the API (100ms).
- Stop after 300‑500 cards so we stay within Supabase free tier limits.

#### 3. Frontend Catalog Page (`app/catalog/page.tsx`)
Rebuild the current catalog page (or create it) to show real data:

- **Server Component** fetches cards from `supabase.from('cards_catalog').select('*')` 
  or uses a custom query with pagination.
- **UI**: Re‑use the existing Kepler card‑grid component (the same dark theme, 
  card shadows, hover effects, gold accents). Each card shows:
  - Image (via the stored `image_url`)
  - Name
  - Set name + number
  - Rarity badge
- **Search & Filter**: Add a client‑side search bar (text filter on name/set) 
  and optional dropdown for rarity/set. The filtering can be done client‑side on 
  the loaded page or via server query parameters – client‑side is fine for MVP.
- **Add to Collection**: Each card should have a “Add to Collection” button 
  that opens a small modal (or redirects) where the authenticated user can 
  specify condition and quantity. For now, just wire the button to insert a 
  row into `user_cards` (assume `user_cards` table exists with columns: 
  `id`, `user_id`, `catalog_card_id`, `condition`, `quantity`, `for_trade`, `wanted`).
  Show a toast or feedback on success.

- **Empty state**: If the catalog is empty, show a message: “Catalog is 
  loading … run the seed script first.”

#### 4. Keep the Kepler DNA
- The catalog page must use the same navigation bar, dark background, serif 
  font, and card styling as the rest of the Kepler app.
- Do not introduce new color schemes or fonts.
