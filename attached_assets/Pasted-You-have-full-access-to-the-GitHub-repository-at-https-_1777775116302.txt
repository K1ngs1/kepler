## Step 3 — Real Data Connections (NO Mock Data)

Every page must query the Supabase database. Remove **all** hardcoded arrays, objects, or placeholder text. Use the exact table and column names from the migration files.

### Key queries to implement:
- **Collection**: `supabase.from('user_cards').select('*, catalog_cards(*)').eq('user_id', userId)`
- **For Trade**: add `.eq('for_trade', true)` to the collection query
- **Catalog**: `supabase.from('catalog_cards').select('*')` with pagination (`.range()`)
- **Trade list**: fetch `trade_offers` where `initiator_id = userId OR recipient_id = userId`, join with `trade_items` and `trade_messages`
- **Trade detail**: fetch a single trade with all items, messages, and participant profiles
- **Real‑time**: subscribe to `trade_offers` and `trade_messages` changes using Supabase Realtime
- **Wishlist matching**: find users who have cards you want and want cards you have

All trade state changes (accept, counter, cancel, confirm) must call the PostgreSQL functions via `supabase.rpc()` — never update trade status directly.
