### 2. OVERALL MISSION
Refactor the project into a **modern web application** with the following stack:
- **Frontend**: Next.js 14 (App Router) with TypeScript, Tailwind CSS, and shadcn/ui.  
  Re‑implement the existing Kepler UI faithfully — keep the same branding, dark theme,

1. **Homepage** – Show the Kepler brand, hero carousel, and “Trending / Hot Trades”

3. **User Authentication** – Sign up / log in with email or Google. Replace the 
   non‑functional “Login” button.
4. **My Collection** – Users add cards from the catalog to their personal collection

5. **Wishlist & Matching** – A dedicated view that shows another user’s wishlist and

   - Propose a trade (select your cards to give / their cards to receive).  
   - Counter‑offer with chats per trade.  
   - Accept a trade → cards are **atomically locked** (cannot be offered elsewhere) 
     using a PostgreSQL function.  
   - Both parties confirm receipt → trade completes.
7. **Real‑Time Updates** – Trade offers, status changes, and chat messages appear 
   instantly without manual refresh.

#### Phase B: Supabase Project Setup & Database Schema
- Add a `.env.local` file with placeholders for `NEXT_PUBLIC_SUPABASE_URL` and 
  `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- Inside the Supabase dashboard SQL editor, run the following (include the complete 
  SQL in your final code output, in a file `supabase/migrations/001_schema.sql`):
  
  **Tables** (all with proper foreign keys and timestamps):
  - `profiles` (extends `auth.users` with `username`, `avatar_url`, `location`, `reputation_score`)
  - `cards_catalog` (id, name, set_name, set_code, number, rarity, image_url, tcgdex_id)
  - `user_cards` (id, user_id, catalog_card_id, condition, quantity, for_trade bool, wanted bool)
  - `trade_offers` (id, initiator_id, recipient_id, status enum: proposed/countered/accepted/completed/cancelled, created_at, updated_at)
  - `trade_offer_items` (id, trade_offer_id, user_id, user_card_id, quantity)
  - `trade_messages` (id, trade_offer_id, sender_id, content, sent_at)
  
  **Triggers**:
  - `update_updated_at_column()` for automatic `updated_at` on relevant tables.
  
  **RLS Policies** (all referencing `auth.uid()`):
  - `user_cards`: users select/insert/update/delete their own rows only.
  - `trade_offers`: users can only see offers where they are initiator or recipient.
  - `trade_messages`: users can only see messages for trades they’re involved in.
  - `cards_catalog`: publicly readable, no one can modify (for now).

  **PostgreSQL Functions** (with `SECURITY DEFINER` to enforce complex rules):
  - `propose_trade(recipient_id, offered_cards json, requested_cards json)`  
    → validates ownership and availability; inserts offer & items.
  - `accept_trade(trade_id uuid)`  
    → verifies caller is recipient, status = 'proposed', then atomically sets all 
      involved cards’ `for_trade = false` and updates status to 'accepted'.
  - `counter_offer(trade_id, new_offered json, new_requested json)`  
    → updates the existing offer and resets status appropriately.
  - `complete_trade(trade_id)`  
    → called when a user confirms receipt; when both confirm, status → 'completed'.
  - `cancel_trade(trade_id)`  
    → only from proposed/countered; marks as 'cancelled'.
  
  **Seed Script**:
  - A Node.js script (`scripts/seed-catalog.mjs`) that fetches first 200 cards from 
    `https://api.tcgdex.net/v2/en/cards` and inserts them into `cards_catalog`.
