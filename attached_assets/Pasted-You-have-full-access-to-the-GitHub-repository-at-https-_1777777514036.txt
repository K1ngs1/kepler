### YOUR MISSION
Transform Kepler from an all-mockup prototype into a fully functional Pokémon card
trading platform by building a real Next.js frontend that talks directly to the
existing Supabase database. The visual design must remain pixel‑identical to the
current index.html. Only the data source changes.

### CRITICAL BACKGROUND — READ FIRST

The repo currently has two separate, disconnected halves:

1. **The frontend (`index.html`)** — a single‑file React 18 app loaded via CDN.
   Every piece of data is hardcoded in the Babel script tag:
   `HERO_SLIDES`, `AUCTIONS_DATA`, `SIDEBAR_LIST`, `LOTS_DATA`, and a `DETAIL`
   object. No Supabase SDK exists. No API calls are made. Auth modals are visual
   only. This is the ONLY working UI.

2. **The database (Supabase)** — fully built with tables (`catalog_cards`,
   `user_cards`, `trade_offers`, `trade_items`, `trade_messages`, `profiles`),
   RLS policies, and five PostgreSQL trade functions (`propose_trade`,
   `accept_trade`, `counter_offer`, `cancel_trade`, `complete_trade`). These
   have never been connected to any frontend.

Your task is to build the bridge between these two halves.
